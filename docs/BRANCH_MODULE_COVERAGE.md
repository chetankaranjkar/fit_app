# Operational branch coverage

Status: **Implemented in the repository. Not migrated. Not deployed.** This is not application-wide branch enforcement. Nullable columns stay nullable until an administrator assigns them. Historical rows are not backfilled.

Classification used below:

- **Shared definition** — organization catalog. No required branch.
- **Branch-owned** — current place, stock, or assignment. Moving it writes a transfer and does not edit older transactions.
- **Historical** — the branch stored on the row is permanent.

## Rules that stay true after a move

- Equipment transfer updates the asset's current branch and appends `GymOps_EquipmentTransfers`. Maintenance rows keep the branch written when the work happened.
- Stock transfer updates the two branch balances and appends ledger rows. Past POS orders are not edited.
- Locker allocation stores the branch at assignment time. A locker transfer updates only the locker's current branch, and only when no assignment is still open.
- A POS line uses the product's stored selling price. A client-submitted unit price is ignored.
- Member transfer from the earlier expand work does not rewrite membership payments.
- Manual attendance stores the branch sent with that check-in. Checkout does not change it.
